# 05 — 商業能力

> 商業視角:紅利點數中心提供哪些能力、各自何時發生、對誰有價值。白話,不談實作。

點數會經歷:**發、用、過期、退、送、併帳**,加上貫穿全程的**查詢**。

## 發點(發放紅利點數)

發放都是**批次入帳**,但有**兩種批次形態**:

- **行銷批次(齊發)**:行銷系統一次對**一大批**顧客(可達百萬級)發放,**人人同金額、同設定**(同效期、同可轉讓)——差別只在對象名單。低頻。
- **結帳批次(聚合,高頻主力)**:各顧客結帳**賺得**的點聚合成一批入帳,**每筆金額不同**(依各自消費)、**設定也可不同**;經**等待期**(如退貨期過)才入帳。
- **其他**:生日禮(定時、指定對象)、客服補償(單人)也走發點,量與觸發不同。
- **等待期與解耦**:結帳點延後入帳,一來**避免對之後退貨的訂單先發了點**,二來讓高頻結帳**批次化、平滑寫入流量**。**訂單與退貨的生命週期歸訂單中心**——點數中心只依訂單中心的指示批次入帳(兩者解耦)。
- **形態差異的重點**:行銷批次 = 一個金額 + 一份名單;結帳批次 = 一堆各自帶金額 / 設定的明細。
- **共通**:發點當下就定各點**何時能用、何時到期、能不能轉送**;不重複發、看得到進度。
- **價值**:回饋消費、拉動回購。

## 用點(折抵)

顧客拿點折抵消費;**面值直接折抵,無換算比例**。

- **時機**:結帳。
- **兩種節奏**:
  - **即時**:當場一步扣掉。
  - **兩階段**(結帳常見):先**預留**(暫扣佔位)→ 付款成功才**確認**(定案)→ 付款失敗或棄單則**取消**(還回)。配合「先扣點、金流成功才算數」。
- **價值**:顧客省錢,商家促成交易。
- **關鍵**:**絕不透支**,有多少用多少。

## 過期

點數有期限,過了就不能用。

- **時機**:到達到期時間。
- **價值**:商家控制長期潛在費用、催顧客盡早回流。
- **關鍵**:過期**即時反映**在餘額(顧客用不到已過期的點),且**留下紀錄**供查。**永久點**(opt-in)無到期,不在此列。

## 退點

顧客退貨或客訴,把當初用掉的點還回。

- **時機**:退貨、消費爭議、客服補救。
- **價值**:顧客拿回權益,商家妥善處理客訴。
- **關鍵**:退點是**有界的還原**,退還一筆**已確認兌換**用掉的點,累計**不能超過**(退貨不生財)。額外加碼**走發點,不走退點**。

## 送點(贈與)

顧客把自己的點送給另一位顧客。

- **時機**:社交贈與、好友分享。
- **價值**:顧客分享人情,商家獲社群擴散。
- **關鍵**:只有**可轉讓**的點能送(補償點通常不可送,防套利);對方收到的點**沿用原到期日**,且**不可再轉給第三人**——跨人一跳即止,斷掉 A→B→C 洗點鏈。

## 併帳(帳號合併)

顧客換帳號(如換手機號),客服把舊帳號的點全數搬到新帳號。

- **時機**:顧客身分變更、帳號整併。
- **價值**:顧客的點不遺失,商家留住顧客。
- **關鍵**:是**同一人**搬家,非贈與他人——**不分可否轉讓全部搬**,搬到新帳號後**逐批原樣保留**可轉讓性,沿用原效期,全程留痕。

## 查詢(最關鍵的能力;詳細規格見 [04-queries](04-queries.md))

分兩種視角,**可見性刻意不同**:

- **顧客**(自助、只看自己、摘要):餘額、點數清單、快過期、過期紀錄、流水。**看流水,不給看明細**。
- **後台**(客服 / 營運 / 商家,完整):顧客完整帳(含消耗明細與回追鏈)、發送狀況、兌換 / 退點盤點、對帳、**商家 Dashboard(全店已實現費用與潛在費用)**。
- **價值**:顧客自助秒查、客服秒答客訴、商家控預算與對帳。
