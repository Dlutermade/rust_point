# 08 — User Story 與驗收條件

> 商業視角。需求以 **User Story** 表達,驗收條件以 **Gherkin**(`Scenario` + `Given`/`When`/`Then`/`And`)。步驟只講**可觀察的商業行為**,不談實作。關鍵字英文、步驟中文、每步一行。

---

## 發點

> **身為** 訂單系統,顧客消費完成後,**我要** 依金額發紅利點給該顧客,**好** 回饋消費。(結帳批次,主力)

```gherkin
Scenario: 消費得紅利(經等待期才入帳)
  Given 顧客完成一筆訂單、賺得紅利
  When 過了等待期(如退貨期)
  Then 系統依消費金額發對應紅利點給該顧客
  And 這批點帶有效期與是否可轉讓

Scenario: 等待期內退貨則不入帳
  Given 顧客賺得的紅利尚在等待期
  When 顧客在等待期內退貨
  Then 該筆紅利不入帳(不會先發了又要收回)
```

> **身為** 行銷 / 營運,**我要** 對一大批顧客齊發同額點數,**好讓** 活動回饋確實送達。(行銷批次)

```gherkin
Scenario: 齊發
  Given 一份顧客名單
  And 設定「每人 100 點、本月底到期」
  When 執行發放
  Then 名單上每位顧客都得到 100 點,效期一致

Scenario: 大量發放看得到進度
  Given 名單達一百萬人
  When 執行發放
  Then 全數顧客完成發放
  And 過程中看得到進度(已發幾成)

Scenario: 重試不重複發放
  Given 一次發放因故中斷後重跑
  When 再次執行同一次發放
  Then 已領過的顧客不再重複領
  And 未領到的顧客補上

Scenario: 可設為不可轉讓
  Given 發放的是補償性質的點
  When 設定該批為不可轉讓
  Then 這批點日後不能被贈送給他人
```

## 用點(折抵)

> **身為** 顧客,**我要** 用點折抵消費,**好** 省錢;且系統絕不讓我透支。

```gherkin
Scenario: 即時折抵
  Given 我有 500 點
  When 我折抵 200 點
  Then 我的餘額變為 300 點

Scenario: 先用快到期的點
  Given 我有兩批點:A 批較快到期、B 批較晚到期
  When 我折抵一筆
  Then 系統先扣 A 批
  And A 批扣完才動用 B 批

Scenario: 餘額不足整筆拒絕
  Given 我有 300 點
  When 我想折抵 400 點
  Then 整筆折抵被拒絕
  And 我的餘額維持 300 點

Scenario: 兩階段—付款成功則定案
  Given 結帳時預留了 400 點
  When 付款成功
  Then 這 400 點正式用掉

Scenario: 兩階段—付款失敗則還點
  Given 結帳時預留了 400 點
  When 付款失敗或顧客主動取消
  Then 這 400 點原封還回我的餘額

Scenario: 棄單逾時自動還點
  Given 結帳時預留了 400 點
  And 顧客遲遲未完成付款
  When 超過保留時限
  Then 系統自動取消預留
  And 400 點還回我的餘額
  And 外部系統得以據此通知我
```

## 過期

> **身為** 商家,**我要** 讓點數在到期後失效並留痕,**好** 控管成本且對顧客透明。

```gherkin
Scenario: 到期即時失效
  Given 一批點的到期時間已屆
  When 到達到期時刻
  Then 該批點立即不再計入可用餘額

Scenario: 過期留痕
  Given 一批點已過期
  When 之後查詢
  Then 查得到「這批何時、過期多少」的紀錄

Scenario: 永久點不過期
  Given 一批永久點(opt-in、無到期)
  When 時間持續流逝
  Then 該批點永不過期
  And 不產生過期紀錄
```

## 退點

> **身為** 客服,**我要** 把顧客某筆已確認消費用掉的點退還,**好** 處理退貨與客訴;但不能退超過。

```gherkin
Scenario: 部分退點
  Given 某筆已確認消費用掉了 400 點
  When 我為這筆消費退還 300 點
  Then 顧客得回 300 點
  And 該筆消費顯示「已退 300、還可退 100」

Scenario: 退點不得超過用掉的
  Given 某筆消費用掉 400 點且已退 300
  When 我想再退 200 點
  Then 被拒絕(超過可退上限)

Scenario: 只退已定案的消費
  Given 一筆尚未定案(仍在預留)的消費
  When 我想退點
  Then 被拒絕(未定案應走取消,不走退點)
```

## 送點

> **身為** 顧客,**我要** 把點送給朋友,**好** 分享回饋。

```gherkin
Scenario: 可轉讓的點才能送
  Given 我持有可轉讓的點
  When 我送 200 點給朋友
  Then 我的餘額少 200 點
  And 朋友的餘額多 200 點

Scenario: 補償點不可送
  Given 我持有補償性質(不可轉讓)的點
  When 我想送出
  Then 被拒絕

Scenario: 送出的點沿用原效期
  Given 我送出的點快到期
  When 朋友收到
  Then 朋友那批點沿用原到期日

Scenario: 收到的點不可再轉
  Given 朋友收到我送的點
  When 朋友想再送給第三人
  Then 被拒絕(收到的贈點不可再轉,一跳即止)
```

## 併帳

> **身為** 客服,**我要** 把顧客舊帳號的點併到新帳號,**好** 在他換帳號時不遺失點數。

```gherkin
Scenario: 全數搬移
  Given 舊帳號有多批點
  When 併入新帳號
  Then 所有點搬到新帳號
  And 沿用原效期
  And 舊帳號清空

Scenario: 不受可轉讓限制
  Given 舊帳號含不可轉讓的點
  When 併帳
  Then 不可轉讓的點也一併搬移(同一人整併,非贈與)

Scenario: 逐批保留可轉讓性
  Given 舊帳號有可轉讓與不可轉讓兩種點
  When 併入新帳號
  Then 原本可轉讓的仍可轉讓
  And 原本不可轉讓的仍不可轉讓
```

## 查詢(顧客)

> **身為** 顧客,**我要** 查自己的點數現況與歷史,**好** 隨時掌握。詳細欄位 / 篩選 / 排序見 [04-queries](04-queries.md)。

```gherkin
Scenario: 查餘額
  Given 我持有多批點
  When 我查餘額
  Then 看到可用總額(只計生效中、未過期)
  And 看到「7 天內將到期 N 點」的提示

Scenario: 查點數清單並依到期排序
  Given 我有多批點
  When 我查點數清單
  Then 依到期日升冪列出各批
  And 每批顯示點數編號、原始 / 剩餘點數、取得日、生效日、到期日、狀態、可否轉讓

Scenario: 篩選快過期點數
  Given 我有點在 7 天內到期
  When 我以「7 天內到期」篩選
  Then 只列出這些即將到期的批次與總額

Scenario: 查過期紀錄
  Given 我有已過期的點
  When 我查過期紀錄
  Then 依過期時間新到舊列出過期時間、過期點數、來源

Scenario: 看流水但不含明細
  Given 我用點折抵過幾筆
  When 我查流水
  Then 依時間看到每筆的時間、類型、變動量、事由、當時餘額
  But 看不到這筆用點各扣了哪幾批(消耗明細不對顧客開放)

Scenario: 預留在流水顯示為處理中
  Given 我有一筆結帳預留尚未定案
  When 我查流水
  Then 該筆顯示為「處理中」
  And 即使該預留稍後被取消,也不向我揭露「扣了又還」的過程
```

## 查詢(後台核對)

> **身為** 客服 / 營運,**我要** 查完整帳、明細與回追鏈,**好** 回答客訴並對帳。

```gherkin
Scenario: 追一筆退點的來龍去脈
  Given 一筆退點
  When 我在後台追查
  Then 追得到它對應哪筆兌換
  And 追得到那筆兌換當初用掉了哪些批

Scenario: 核對某兌換已退與可退
  Given 一筆已確認兌換用了 400 點且已退 300
  When 我查該兌換
  Then 顯示已退 300、還可退 100

Scenario: 對帳批次守恆
  Given 任一批點
  When 我核對
  Then 原始點數 = 剩餘點數 + 已消耗點數
```
