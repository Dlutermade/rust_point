# 04 — 查詢規格(詳細)

> 商業視角。**查詢是最關鍵的能力**——顧客體驗與客服效率都靠它,也是商家控預算的依據。逐一列出每個查詢的**用途、顯示欄位、篩選、排序、可見性**。
>
> **這是「畫面上的查詢」規格,不代表 API 要這樣設計。** 欄位指畫面看到的資訊(非資料庫欄位);一個畫面可能由多支 API 組成、或一支 API 服務多個畫面——API 設計是技術視角的事。

## 可見性總則(最重要)

| | 顧客(自助) | 後台(客服 / 營運 / 商家) |
|--|-------------|--------------------------|
| 範圍 | **只有自己的** | 任一顧客、跨顧客、全店 |
| 深度 | **摘要層級** | **完整**:含消耗明細與回追鏈 |
| **看得到明細嗎?** | **看不到**(看流水,不給看明細) | 看得到(吃了哪幾批、退對應哪筆) |

> 顧客看「我有多少、怎麼來怎麼去」;**「這筆用點各扣了哪幾批、退點對應哪筆兌換」是後台核對用的明細,顧客不需要也不給看。**

---

# 顧客視角

## 1. 點數餘額

- **用途**:一眼看現在有多少可用。
- **顯示**:可用點數總額(只計已生效、未過期);「**7 天內將到期 N 點**」提示。
- (待 PO 確認)是否顯示「未生效、即將入袋」的總額。

## 2. 點數清單(逐批)

- **用途**:看每一批點的狀態與效期。
- **每筆顯示欄位**:

  | 欄位 | 說明 |
  |------|------|
  | 點數編號 | 這批的識別碼;顧客 / 客服可據以指名特定一批 |
  | 事由 / 來源 | 白話標籤(來源見下) |
  | 原始點數 | 這批發了多少 |
  | 剩餘點數 | 還剩多少 |
  | 取得日 | 這批入手的日期 |
  | 生效日 | 何時開始可用 |
  | 到期日 | 何時失效(永久點顯示「永久」) |
  | 狀態 | 生效中 / 未生效 / 已用完 / 已過期 |
  | 可否轉讓 | 能不能送人 |

- **事由的來源**:**行銷批次**的事由來自發放時外部系統打進來的內容(活動名等);**結帳 / 退點 / 贈點 / 併入**批沒有外部文字,事由由產生它的那筆流水動態生成(如「訂單回饋」「訂單退點」「好友贈送」)。
- **預設範圍**:**只顯示「生效中」**;其他狀態切換篩選才看。
- **篩選**:狀態、快到期(顧客自選,如 7 天內)、來源類型、取得日期區間、是否可轉讓。
- **排序**:到期日(**預設升冪**,與「先用快到期」一致)、取得日、剩餘點數。

## 3. 快過期(提示 + 篩選,非獨立查詢)

- **餘額頁**:固定顯示「**7 天內**將到期 N 點」。
- **點數清單**:由顧客自己用「快到期」篩選查看。

## 4. 過期紀錄

- **用途**:回答「我的點怎麼不見了」。**唯看**。
- **每筆顯示**:過期時間、過期點數、來源 / 事由、原效期。
- **排序**:過期時間新到舊。**篩選**:日期區間。

## 5. 流水(異動紀錄)— 不給看明細

- **用途**:看點數怎麼來、怎麼去。
- **每筆顯示欄位**:時間、類型(得點 / 用點 / 退點 / 過期 / 收到贈點 / 送出贈點 / 帳號併入)、變動量(±)、事由、**當時餘額**(running balance)。
- **預留呈現(避免客訴)**:**預留中與已取消的預留,一律顯示為「處理中」**——不揭露「預留 → 取消」的內部週期,免得顧客看到「扣了又還」而困惑。只有**確認後**才顯示為正式「用點」。
- **不顯示(關鍵)**:消耗明細(各扣哪幾批)、退點對應哪筆兌換、任何回追鏈——**屬後台**。
- **篩選**:類型、日期區間。**排序**:時間新到舊。

# 後台視角

## A. 顧客完整帳(客服個案)

- 顧客看得到的全部,**再加**:消耗明細(每筆用點 / 送出 / 併出各扣哪幾批)、回追鏈(退點對應哪筆兌換、贈點來自誰、併入來自哪帳號)、預留的真實狀態(不做「處理中」美化)。

## B. 發送狀況 Table(營運監控)

- 每一筆發點 / 發送的**狀態一覽表**:活動 / 來源、對象人數、已入帳、略過(重複領)、狀態(處理中 / 完成 / 失敗)、時間、失敗原因。
- **用途**:盯每次發送有沒有發完、有沒有失敗、要不要重跑。後台不可能只看流水。

## C. 兌換 / 退點 盤點

- **兌換列表**(依狀態 / 日期);單筆含「已退多少、還可退多少」。**退點列表**(掛在兌換下)。

## D. 商家點數 Dashboard(經營 / 預算)★

點數不是顧客儲值,所以**發點不是費用、只是承諾**;真正的費用在顧客「用掉且沒被退 / 取消」時才發生:

- **潛在費用(未實現)**:未到期、還能被用的流通點數總額;顧客用掉才會變費用。控預算看這上限。
- **已實現費用 ★**:顧客用掉、且未被退 / 取消的點淨額(= 確認兌換 − 退點 − 取消)。商家真正的費用(= 折扣),會進未來的**對帳單 / 費用單**。
- **過期**:沒變成費用就消滅的承諾(商家省下)。
- **趨勢**(各期間):已發(增潛在費用)/ 已用確認(實現費用)/ 已退・已取消(沖回)/ 已過期(承諾蒸發);近 7 / 30 天即將到期。

## E. 對帳(核對真相)

- **批次守恆**:每批「原始 − 剩餘 = 已消耗」對得上。
- **餘額 vs 帳本淨額**:顧客餘額與所有異動加總一致。
- **來源匯總**:某活動 / 期間發了多少、用了多少、退了多少、過期多少。

## 給 PO 的核對清單

1. 顧客 5 個查詢的**顯示欄位**是否齊全?(§1 是否顯示「未生效」總額待定。)
2. ✅ 點數清單:點數編號 / 取得日、預設只顯示生效中、事由來源。
3. ✅ 快過期:餘額頁 7 天提示 + 清單顧客自選篩選。
4. ✅ 流水:顯示「當時餘額」;預留中 / 已取消預留顯示「處理中」。
5. 後台 A–E(顧客完整帳、發送 Table、兌換 / 退點盤點、**商家 Dashboard 費用 / 預算**、對帳)夠不夠?
