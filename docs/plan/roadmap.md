# 產品路線圖(Roadmap)

> 各產品(bounded context /「中心」)的建置順序。每個中心**各自成家、彼此解耦**;**前台中心是整合面**——每建好一個中心,就回前台把它「長出來」(垂直切片、逐一在前台顯化)。
> 現階段:**先規劃、不實作**。

## 建置順序

| # | 做什麼 | 重點 |
|---|--------|------|
| 1 | **前台中心** | 前台頁面系統:Tree 定 layout、後台客製化(內容 / 排版 / 曝光版位)。**不含**登入、商品、結帳、購物 |
| 2 | **商品中心** | 建「商品」context |
| 3 | ↩ **回前台中心** | 補**商品模組 + 商品頁** |
| 4 | **訂單中心** | 建「訂單」context |
| 5 | ↩ **回前台中心** | 補**結帳功能** |
| 6 | ↩ **回商品中心** | 定義**商品折扣** |

## 後段(位置待定,待 PO 補)

- **會員 / 登入中心**:結帳與會員功能會需要;確切位置待定(可能在第 5 步結帳前後)。
- **紅利點數中心**:已規劃、**parked**(見 `01-point-center/`);等前台 / 商品 / 訂單 / 會員就緒後回來接(前台顯示點數、結帳折抵等)。

## 為什麼這樣排

前台先立起來當**底座**,後面每個中心都有地方落地、馬上看得到、測得到——這就是「先做前台才通順」。

## 註

- **plan 資料夾編號 = 建立順序 / ID,不等於建置順序**:`01-point-center`(點數,已規劃 parked)、`02-storefront-center`(前台中心,建置第 1 步,進行中)。
