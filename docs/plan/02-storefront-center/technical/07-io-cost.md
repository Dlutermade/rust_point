# 07 — IO / 成本盤點

> 技術視角:每條路徑的 IO / 渲染成本。**熱路徑幾乎不打 DB** 是高 RPS 的根。
> 先規劃、不實作。

## 計數約定

- 最在意**載頁熱路徑**;編輯 / 發布是低頻。
- DB 一次查詢 = 1 IO;快取命中 = 記憶體 / Valkey 讀;渲染 = CPU。

## 各路徑

| 路徑 | DB | 快取 | 其他 | 說明 |
|------|----|------|------|------|
| **載一頁(v1 全靜態,cache 命中)** | **0** | 1 讀 | — | **熱路徑不打 DB**;吐 Bytes。RPS 命門 |
| 載一頁(cache miss) | 1(讀 published) | 1 寫回 | CPU 組裝 | 少見;miss 後回填 |
| 載一頁(v3 含個人化) | 0 | 1 靜態 + N segment 片段 | feature store 查(Valkey) | per-user 走 segment 快取 + 串流 |
| 存草稿 | 1 UPDATE(`pages.draft`) | — | — | 低頻 |
| **發布** | 1 UPDATE(draft→published, ver++) | 清該頁鍵 | 編譯 render plan(CPU) | 低頻;**重工在此、不在熱路徑** |
| 區段組發布 | 1 UPDATE | 清所有引用頁 | — | 低頻;影響面大 |
| 上傳圖片 | 1 INSERT(assets) | — | GCS/FS 寫 | 低頻 |
| **編輯即時預覽** | **0** | — | client WC 本地重繪 | **完全不打網路** |

## 重點

- **載頁熱路徑 = 0 DB + 1 快取讀**——這就是高 RPS 的根。所有重工(編譯、渲染)挪到**發布時**(低頻)。
- 呼應舊系統的效能教訓:**不在每請求做重運算**;個人化也走「查表」不運算(見 [02](02-render-engine.md))。
