# 00 — 技術視角總覽(前台中心)

> 技術視角:系統形狀、主要部件、約定。商業視角見 [`../business/`](../business/)。
> **先規劃、不實作。** ⚠️ 早期草擬,結構待 PO 核對。
> 「use case」在此指**時序圖**。

## 這不是純後端服務,是全端 web app

與 `point-center`(純 Rust 後端 + 多 pod)**不同**:前台中心同時是「**訪客看的網站**」+「**商家用的編輯器**」,**Rust 後端 + React 前端、MPA + SSR**。所以**不套用點數的沙漏**,改用「訪客 / 商家 / 共用核心 / 資料」的分面。

## 形狀:三面 + 資料底座

```
        訪客(瀏覽)                     商家(後台編輯)
            │ 每頁網址(MPA)                │ 編輯器(React SPA)
   ┌────────▼──────────┐          ┌────────▼───────────┐
   │ 公開頁服務(SSR)   │          │ 編輯 API           │
   │ 只載用到的區塊     │          │ (讀寫頁面/區塊/    │
   │ SEO / 第三方腳本   │          │  設定/草稿/發布)   │
   └────────┬──────────┘          └────────┬───────────┘
            └──────────── 共用核心 ──────────┘
              區塊型別系統(schema + React 元件)
              動作 / event routing · 動態資料接點(未來)
   ══════════════════════════════════════════════════════
     資料存取:頁面 JSON 樹 · 區段組 · 全站設定 · 草稿/發布
              · 多租戶隔離 · 圖片資產(GCS/FS)· 快取
```

## 各層文件(建置中,順序待定)

| 面 | 內容 |
|----|------|
| **訪客端渲染** | SSR / MPA / 每頁路由 / SEO / 逐頁 code-split / 第三方腳本載入器 |
| **商家端編輯器** | React 編輯器 / 即時預覽(iframe)/ 依 schema 生成設定表單 / 拖拉樹 / 多裝置 |
| **對外 API** | 編輯 API(頁面/區塊/設定/發布)+ 公開頁服務 |
| **區塊型別系統** | 型別註冊 / schema / 型別↔React 元件映射 / 動作 routing / 動態資料接點(extension block) |
| **資料存取** | 頁面 JSON 樹、區段組、全站設定、草稿↔發布版本、多租戶、圖片資產、快取 |
| **成本盤點** | 每條路徑(載一頁 / 發布 / 編輯儲存)的 IO 與渲染成本 |

## 約定

- **參考業界主流的「內容 / 組頁模型」**(sections / blocks ≤5 層、schema+preset、section-group、多裝置值)——**渲染方式不沿用它**(走自己的 Rust 引擎)。
- **技術定調**(詳 [01 選型與引擎](01-decisions.md)):前台 = **純 Rust SSR 引擎**(高 RPS、連個人化都 SSR);區塊 = **Web Components(Lit)**(標準、一次寫、負責互動);編輯器 = **React + Antd + TanStack Query / Router**,即時預覽 client-side、編輯不重打網路。
- **不走樣板 DSL**:區塊我們自己做、商家只組合不寫碼;不需要 Shopify / 一線 storefront builder 那種給外部工程師的 Liquid / 自建模板 DSL。
- **未來 seam**:開放外部人做區塊 → plugin / extension(仍是 WC + API,不是 DSL)。
- **先規劃、不實作。**
