# 01 — 邊界與非目標

> 商業視角:前台中心管什麼、不管什麼、刻意不做什麼。
> ⚠️ 待 PO 核對。詞彙見 [03](03-glossary.md),頁面模型見 [04](04-page-model.md)。

## 管(v1)

- **多租戶**:一套系統服務多商家,每商家各自的站。
- **只做 web**:純網頁前台(MPA);**不做原生 App**。
- **拖拉組頁**:三種可編輯實體(**首頁模板 / 頁首模板 / 頁尾模板**);內容 = **區塊樹,可巢狀(≤ 5 層)**;客製化**內容 + 排版**。
- **頁首 / 頁尾**:各自可有多份,其中一份是**站台預設**;首頁可指定要套哪份(**兩者可分開指定**),不指定就跟隨站台預設。
- **首頁多版本 + 生效條件**:同一站可有多份首頁模板(常態版 / 周年慶版 / 會員版…),帶**檔期 / 受眾 / 來源 / 優先序**,訪客上門當下解析出一份;**常態版永久兜底**。
- **區塊庫**:9 個**組合原語** —— 標題 / 文字 / 圖片 / 圖示 / 按鈕 / 容器 / 疊層 / 分隔線 / 間距。區塊型別 = **設定欄位(schema)+ preset**。
- **桌機 / 手機**:**顯示裝置**(全部裝置 / 僅電腦 / 僅手機)+ **分裝置設定值**(排法類欄位電腦與手機各存一份)。一棵樹、一次發布。
- **SEO**:每份模板自己的標題 / 描述。
- **草稿 / 發布**:發布即凍結,要改就複製一份;可暫停 / 恢復、調優先序;每步留**異動紀錄**。
- **全站設定**:品牌色 / 字型 / logo。
- **後台選店**:進後台先輸入**店號**選定要編哪個站,**不驗證身分**(v1 沒有帳號系統)。
- **互動由商家指定**:設定按鈕等「按下去做什麼」,從系統動作目錄挑;第三方腳本編排。
- **產品 NFR**:SSR / SEO、只載用到的(載得快)。

## v1 不含(依路線圖後續才回來補)

- **身分驗證 / 會員**。後台以**店號選店**代替登入(不驗證);前台以**主機名**解析租戶。真正的帳號、權限、會員態等會員中心進場才做。
- **網址(slug)**。v1 只有首頁,網址恆為 `/`。slug 描述的是「一個網址」而模板是「這個網址的一份呈現」(**一對多** —— 常態版與周年慶版共用同一個網址),所以它不是模板的屬性;等第二種頁面種類(活動頁 / 自訂頁)進來,那時才知道它該住哪。
- **商品**(先做商品中心 → 再回前台補商品頁 / 分類頁 / 商品區塊)。
- **結帳 / 購物**(先做訂單中心 → 再回前台補結帳)。

## 延後(留 seam,不首發)

- **資料型區塊 + 資源選擇器 + 動態綁定 / metafield**(等商品、點數等中心提供資料)。
- **extension / app block**(外部中心以區塊注入前台)。
- **局部 AJAX 重繪**(不整頁重載的即時更新)。
- **版本歷史 / 回溯**(v1 只有草稿 / 發布 + 複製)、A/B、多語、多主題。
- **受眾細分**(v1 只看登入態三態;會員等級 / segment 等會員中心進場)。

## 不管(交給別的中心,解耦)

- 商品、訂單、會員、金流、(未來)點數——各自獨立中心;**前台只負責「呈現與編排」**,資料由各中心提供,不碰它們的邏輯。

## 技術待辦(留給技術視角,商業層不決定)

- **MPA**、**Rust + React 全端**、**SSR 引擎**(業界主流電商建站平台多自建編譯式模板引擎;我們用 Rust)。
- 模板內容存 JSON 樹、只載用到的區塊型別(逐頁 code-split)、巢狀與分裝置值的渲染。
- 第三方腳本載入器、**event routing 到動作(含 tracking / custom script)的實作與動作目錄**。
