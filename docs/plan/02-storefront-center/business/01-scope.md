# 01 — 邊界與非目標

> 商業視角:前台中心管什麼、不管什麼、刻意不做什麼。模型對標業界主流組頁模型。
> ⚠️ 早期草擬,待 PO 核對。

## 管(v1)

- **多租戶**:一套系統服務多商家,每商家各自的站。
- **只做 web**:純網頁前台(MPA);**不做原生 App**。
- **拖拉組頁**:頁面 = **區段清單**;區段內含**區塊,可巢狀(≤ 5 層)**;客製化**內容 + 排版**。
- **共用區段組**:header / footer /(公告),設一次套全站。
- **區塊庫**:區塊型別 = **設定欄位(schema)+ preset**。
- **v1 區塊型別**:banner(含 Hero)、文字清單(如最新消息)、圖片、**排版容器**(欄 / 列)。
- **多裝置值**:設定可分桌機 / 手機。
- **頁面實例**:網址 slug、**SEO(標題 / 描述)**、**草稿 / 發布**。
- **全站設定**:品牌色 / 字型 / logo。
- **互動由商家指定**:設定按鈕等「按下去做什麼」,從系統動作目錄挑;第三方腳本編排。
- **產品 NFR**:SSR / SEO、只載用到的(載得快)。

## v1 不含(依路線圖後續才回來補)

- **登入 / 會員**。
- **商品**(先做商品中心 → 再回前台補商品頁 / 分類頁 / 商品區塊)。
- **結帳 / 購物**(先做訂單中心 → 再回前台補結帳)。

## 延後(留 seam,對標業界主流但不首發)

- **資料型區塊 + 資源選擇器 + 動態綁定 / metafield**(等商品、點數等中心提供資料)。
- **extension / app block**(外部中心以區塊注入前台)。
- **區段局部 AJAX 重繪**(不整頁重載的即時更新)。
- **版本歷史 / 回溯**(v1 只有草稿 / 發布)、排程上架、A/B、個人化、多語、多主題。

## 不管(交給別的中心,解耦)

- 商品、訂單、會員、金流、(未來)點數——各自獨立中心;**前台只負責「呈現與編排」**,資料由各中心提供,不碰它們的邏輯。

## 技術待辦(留給技術視角,商業層不決定)

- **MPA**、**Rust + React 全端**、**SSR 引擎**(業界主流電商建站平台多自建編譯式模板引擎;我們用 Rust)。
- 頁面存成 JSON 樹、只載用到的區塊型別(逐頁 code-split)、巢狀與多裝置值的渲染。
- 第三方腳本載入器、**event routing 到動作(含 tracking / custom script)的實作與動作目錄**。
