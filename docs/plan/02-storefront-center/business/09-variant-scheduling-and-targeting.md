# 09 — 變體的生效與定向(檔期 / 受眾 / 優先序)

> 商業視角:同一個版位 / 頁面可以準備**多個版本(變體)**,由系統依「**現在時間 + 訪客是誰 + 從哪來**」決定訪客當下看到哪一個。以情境 + ASCII 示意,零技術。
> ⚠️ 草擬,待 PO 核對。

## 一個版位 = 多個變體,一次只呈現一個

頁首、頁尾、首頁(未來每種頁面)都能準備**多個變體**——常態版、周年慶版、會員版…。訪客某一刻只會看到**其中一個**。

「哪一個生效」**不是後台手動勾一個開關**,而是每個變體**帶自己的生效條件**,系統在訪客上門的當下**算出來**。

## ⚠️ 範圍:生效是「頁面」的事,頁首/頁尾是外框

以下的排程 / 受眾 / 優先序,**真正的家是「頁面」**(首頁,及未來商品頁 / landing)——決定「這個訪客現在看哪一版**頁面體驗**」。

**頁首 / 頁尾是頁面套進來的「外框(chrome)」,用更簡單的模型,不跑這整套**:

- **一個外框庫 + 站台預設**:哪個頁首 / 頁尾是全站標準。
- **頁面可覆寫**:某個頁面可挑自己的頁首 / 頁尾;不挑就吃站台預設。
- **頁首內部個人化**:登入顯示「會員中心」、未登入顯示「登入」、購物車數字… 是**同一個頁首元件內部**隨人變,**不是兩個排程變體**。

→ 頁首 / 頁尾**不需要**下面的受眾 / 來源 resolve;複雜度集中在**頁面**。下文的完整模型主要講**頁面**。

## 決定「呈現哪一個」的維度

每個變體可(選擇性)設定四件事:

```
變體:周年慶頁首
├─ 檔期(時間) : 2026-08-01 00:00 ─ 08-14 23:59   ← 沒設 = 常態(永久生效)
├─ 受眾(是誰) : 有登入 / 無登入 / 不判斷(三態)   ← v1 只看登入;會員等級 / 分眾之後
├─ 來源(從哪) : utm 來路 / 語系 / 地理位置         ← 沒設 = 任何來源
└─ 優先序       : 數字越大越優先(重疊時誰勝)
```

## 永遠有一個「常態版」兜底

每個版位**一定有一個常態版(永久預設)**:**不設任何條件**、**優先序最低**。當沒有任何特別變體符合當下情況,訪客就看它。→ 畫面**永遠有東西**,不會開天窗。

## 商家怎麼想:一條時間軸

```
        7/31        8/1 ─────────── 8/14        8/15
常態版 ─████████──┐             ┌──███████████──►   (永久,墊底)
周年慶版          └──██████████──┘                    (檔期到自動換回常態)
```

檔期一到,周年慶版**自動生效**;檔期一過,**自動換回常態版**——商家不用半夜手動切。

## 幾個真實情境

- **檔期**:周年慶頁首 8/1–8/14 生效,到期回常態。
- **會員專屬**:金卡會員看到帶專屬入口的頁首;非會員看常態。
- **廣告來路**:從某夏季廣告(utm)點進來的訪客,看到對應活動的頁首。
- **重疊**:同一刻「周年慶版」與「金卡會員版」都符合 → 比**優先序**,高者勝。

## 「使用中」的新意義

後台不再是「把某個變體設為使用中」這一個靜態動作;而是**替每個變體設定它的生效規則**,系統依訪客當下決定看哪個。常態版就是那個「**沒人符合時就它**」的底。

## 生命週期:草稿 → 發布(發布後凍結,改用複製)

- **草稿**:新增後進入草稿,**內容與生效條件都可改**。存檔時可選**「儲存為草稿」**或**「直接發布」**。草稿**不會上線**。
- **發布後凍結**:為了**可追溯、不誤改線上**,一經發布**內容與生效條件就不能再改**。要調整就**複製一份**成新變體去改——舊的留著當紀錄。

已發布的變體:
- **可做**:調整**優先序**、**暫停 / 恢復**、**複製**。
- **不可做**:改內容 / 改檔期 / 改受眾 → 請複製新版。
- 開啟它只會**檢視(唯讀)**,不是編輯。

**異動紀錄**:每次 建立 / 複製 / 調優先序 / 暫停 / 恢復,後台都留紀錄(誰、何時、做了什麼),隨時查得到「某個時間點線上是哪一版」。

（技術上怎麼解析、怎麼保證高效,見 technical/10。）
